关键机制

  1. 三级降级抓取：A syndication（免登录但匿名额度易 429）→ B Nitter RSS（实例缓存直连 + twiiit 轮换发现，按「<?xml 开头」验收防 CF/Anubis 挑战页）→ C Cookie 直连（实验性）。任一层成功即止，全失败才整体标红。
  2. 增量去重：X 按置顶雪花 id 截断（无更新时 0 入库/0 AI/0 推送）；RSS 逐条扫描由 UNIQUE(source_id, tweet_id) 保证幂等（不再按首条 GUID 短路——置顶条目或非首位新增不会漏采），位点 rss_top_{id} 仅在入库完成后推进、仅作追踪参考。
  3. 排序与时区：雪花 ID 全局时间有序，列表按 CAST(tweet_id AS INTEGER) DESC 排序，补抓批次内不乱序；published_at 存 GMT 裸值，前端按 UTC 解析转本地时区显示。
  4. AI 额度保护：自动阶段每轮限 auto_limit 条；研判失败的推文标 ai_status=error 不自动重试；无地理信息的推文标「未知」不被补标任务反复处理。
  5. 模拟模式：通道凭据留空 = 模拟——消息照常经模板生成并写入推送日志（标「模拟成功」），不外发；填入凭据即真实推送，无需重启。
  6. 媒体代理：/api/media?url=… 服务端经抓取代理拉取 pbs.twimg.com 原图（域名白名单校验），客户端无需直连 X 图片 CDN，并带 24h 缓存头。
  7. 通道多实例：channels.{key}.instances 列表（每实例 name/凭据/enabled/filters 四维筛选），旧单实例结构运行时兼容读取；推送按实例循环——全局过滤后每实例再过自己的 filters，推送日志 channel 列记「类型·实例名」；企微 45009 限频自动退避（15s/30s×3 次）+发送节奏 4s。
  8. 推送门控：AI 实时开启时，仅 ai_status='ok' 的推文进入推送（失败重试 2 轮后附错误说明放行）——保证推送内容必经研判；推送后标记 pushed 防重复。
  9. 混合分类：16 类情报分类采用 脚本规则（9 组关键词零成本命中）+ AI 批量兜底（每 10 条一次调用）双通道；新推文研判时顺带标注分类。
  10. syndication 熔断：连续 3 轮失败后 30 分钟内跳过该层（省每轮 15s+ 无效等待），成功自动复位。
  11. 报告任务桥接：系统只做任务管理与验收（建任务/线索包落盘/claim 原子领取/复跑机械门禁/推送），报告正文由外部 report-writer Agent 产出——验收不信任 Agent 自报 gate 结果，系统必须自己复跑已配置的门禁脚本（解释器默认当前 Python，可配 report.gate_python，exit 0=已交付待推，否则待人工，宁拦住不放过）；交付路径必须在 data/report_tasks 下（safe_report_path），绝对路径/穿越一律转待人工；推送按通道能力分发（企微附件两步法，其余通道摘要+内网获取提示）。
  12. AI 模型拉取：GET {base_url}/models（OpenAI 兼容标准端点）→ 前端 datalist 下拉，仍可手输；先保存配置再拉取，保证用最新地址与 Key。

认证与授权

  • 浏览器：/login → POST /api/auth/login → HttpOnly Cookie（SameSite=Lax，12h）+ CSRF； 写请求必须带 X-CSRF-Token。
  • 脚本/Agent：Authorization: Bearer xintel_…，角色 read / write / admin（逐端点依赖声明）。
  • 未初始化管理员时一律 503，不存在匿名兜底；Token 吊销即时失效，完整值仅创建时显示一次。
  • 初始化/重置：本机 data/admin_init.txt（用户名:密码，密码≥8 位）。

事件聚合与审核（版本 / 指纹 / 快照）

  • 身份契约：evidence_id = 关联表行 id（仅审计）· tweet_id = 业务身份； 展示/跳转/解除/拆分/导出一律使用 tweet_id（查询全部唯一别名，collected_at 与 linked_at 分开）。
  • 证据指纹：成员 + 每条证据 analysis_version 的 SHA1；底层情报变化 → 读路径检测 → 事件版本推进 + evidence_changed 留痕（幂等）。
  • 审核三态：valid（绑定当前版本且指纹一致）/ stale（历史决定，页面标注 "需重新审核"）/ none；审核写入锁内复验版本并绑定指纹，同一版本只能一条决定。
  • 写事务：内容修改/版本检查/推进/审计同一事务（UPDATE … WHERE version=?，并发只允许一个成功）； 加/移证据、合并、拆分为单事务；拆分零有效成员直接失败且不创建空事件。
  • 导出一致性：独立只读连接（WAL 快照）读取全部数据，与写请求完全隔离；四类导出同口径。

统计与投递口径

  • 来源：总数 = X + RSS；启用数 = 两类启用之和（启用但异常仍计入启用）；逐源四态 ok / error / unknown / disabled（启用但无抓取记录 = unknown，不冒充正常）；聚合健康 normal / partial_error / error / unknown / idle，一轮 X 成功不掩盖 RSS 已知失败。
  • 推送成功率：真实/模拟分列；分母 = 真实尝试（逻辑投递，非重试次数），仅模拟时显示 "无真实样本"，不显示 100%。"今日"与"近 24 小时"为不同窗口，不强行相等。
  • AI 写入：模型计算与提交职责分离；成功经 apply_ai_result 原子提交（版本+人工保护）， 失败/配额状态经 update_ai_guarded 写回（不覆盖期间人工修改，冲突留审计）； 429/额度耗尽立即停止本轮后续调用。

报告编写工作台（协作写作 · 一键 Word）

  • 协作内核：app/doccollab.py 基于 pycrdt（Yjs CRDT）——ASGI WebSocket（/ws/docs/{doc_uid}） 挂载于 FastAPI；on_connect 统一鉴权（会话 Cookie / 一次性 ticket / Bearer + Origin 校验 + 文档 ACL）。 自研 SQLite YStore 把每个 CRDT 更新落主库 doc_updates（房间重建=按 seq 回放；初稿仅在日志为空时从模板发布版初始化一次）， 落库成功后推进房间 awareness 的 saved_seq → 前端「已同步」为服务端持久化确认。
  • 房间生命周期：按需构建、空房自动清理（同步清理本模块映射）；修订循环每 3s 对比文本哈希写 doc_revisions(kind=save)； 房间移除后做最终快照。单进程约束：房间操作仅在事件循环线程，REST 线程经 run_coroutine_threadsafe 桥接。
  • 只读强制（服务端）：无写权限连接的 SYNC_STEP2/SYNC_UPDATE 在 Channel 包装层被丢弃——服务端永不应用其更新，前端禁用仅为体验。
  • 受控修改：pycrdt Text 索引为 UTF-8 字节偏移——所有替换自算字节边界（锚点唯一匹配，零/多匹配明确失败）， 中文/emoji/组合字符精确；base_rev 乐观锁 + client_id 幂等；建议接受/拒绝逐条留痕。
  • Word 导出：app/wordexport.py——原子捕获不可变修订（kind=export）→ pandoc 子进程 （list 传参、timeout、受控临时目录、--resource-path 限本目录；远程图片不抓取、明确缺图提示）→ ZIP/OOXML 部件与正文探针校验 → 内容哈希缓存复用；app/assets/reference.docx（宋体/黑体）由 scripts/make_reference_docx.py 生成。导出不改审核/交付/推送状态，与报告任务门禁独立。

出站与恢复安全

  • 受控抓取：RSS/媒体/来源测试统一 fetch_limited——仅 http/https、重定向逐跳校验、 响应 ≤8MB、显式超时；私网/回环/链路本地默认拦截，按用途白名单精确放行， AI 网关白名单不会扩大到 RSS/媒体/webhook。
  • 备份恢复：SQLite online backup（含 WAL 未检查点数据）；restore_to 默认 强制 scheduler.enabled=false + outbound.enable=false（备份原件不动）并清除旧 Token/会话， 摘要区分"原件哈希"与"恢复变更"；启动后需实际验证（healthz、调度暂停日志、抓取/推送日志为空）。
