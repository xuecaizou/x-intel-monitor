3. 监控账号管理

  • 添加：输入 @用户名 → 选首抓条数（默认 10，可选 20/30/50）→ 添加。首抓按设置回溯历史推文。
  • 频率：每账号独立设置（跟随全局 / 5 分钟~2 小时），未到期的轮次自动跳过。
  • 增量：置顶推文 id 短路——X 无新推文时该账号 0 处理，不重复入库/耗 AI/推送。
  • 启停/重命名/删除：账号行操作即时生效。
  • 数据核验：「抓取日志」面板每轮记录各账号分层追踪明细（哪层成功/失败/耗时），可回溯定位。

4. AI 研判 / 翻译 / 地理标签 / 情报分类

维度内容
威胁研判威胁类型、建议等级（critical~info）、态势评估（≤150 字）、处置建议、置信度、IOC 列表
智能翻译标题式中文概括 + 完整中文翻译（专有名词/IOC/CVE 不译）
地理标签国家 → 省/州 → 城市 三级地区（未提及如实留空）、涉事单位全称、所属行业；判定依据记入 geo_basis（flag/geo/ai/soft_org）。企业总部不视为涉事国家，披露机构（FBI/CISA 等）不参与判定
关键词标签AI 研判时提取 ≤10 个情报要素标签：威胁手法（木马/勒索/数据泄露/0day…）、技术要素（C2/僵尸网络…）、恶意家族、威胁组织、涉事企业、攻防双方国家；英文缩写一律译成「英文（中文说明）」（如 C2（命令与控制服务器）、RAT（远程访问木马））；存于 tags JSON 列。存量数据用 python backfill_tags.py [--limit N] 轻量回填（顺带补行业/单位/省州缺口，自动提交短事务可断点续跑）
情报分类16 类标准：预警/参考/舆论/政策/动态/态势/主体情报 + 木马/钓鱼网站/钓鱼邮件/水坑/暴破扫描/僵尸网络/蠕虫/网页篡改/数据泄露线索（脚本规则优先 + AI 兜底）

触发方式：新推文自动处理（实时开关控制）或推文卡手动按钮；「补齐地区标签」「AI 分类」按钮批量处理历史数据。研判失败的推文自动重试 2 轮后放行推送（附错误说明），不阻塞管线。

AI 实时开关：推文流标题栏一键启停自动研判/翻译。关闭后新推文仅入库不调 AI（推原文），手动按钮不受影响。

5. 推送与推送过滤

  • 四通道：企业微信群机器人 / 钉钉机器人（加签）/ PushPlus / WxPusher，凭据面板内联编辑（脱敏回显），留空 = 模拟模式。
  • 推送门控：AI 实时开启时，仅已研判成功的推文进入推送（重试 2 轮失败后附错误说明放行）——保证推送内容必经研判。
  • 推送策略：摘要合并（≤8 条，含国家标注/译文）+ AI 判为 critical/high 的推文即时单推（含截图原图/中英对照/研判/建议）。
  • 企业微信附图：即时单推以 image 消息类型直传截图原图（base64，无需公网 URL），图片直接显示在企微消息中。
  • 推送过滤六维（2026-11-07 扩展）：最低等级 / 情报分类白名单（精确匹配） / 国家白名单 / 行业白名单 / 关键词标签白名单（与卡片橙标精确一致） / 关键词白名单，对摘要与即时推送同时生效；被过滤轮次记入日志。命名规则编辑器同六维，供通道实例按需绑定。白名单输入为「标记式」控件：下拉选常用值（来自 facets 动态计数）+ 自由输入不可预测的值回车添加，chips 可删、重复自动去重；关键词框保持自由文本。条件组合方式可选「且 / 或」（默认且）：且=全部满足才推送；或=任一非空维度满足即推送（维度内多值始终是或）；空条件不参与。

6. 日志与运维

  • 抓取日志：侧栏「抓取日志」面板（点击展开），每轮记录 触发方式/到期与成功账号数/新增与 AI 数/分层追踪明细（如 syndication✗429 → nitter✓20条/1.5s），SQLite 持久化保留最近 500 轮。
  • 推送日志：「推送记录」面板，含推送全文 Markdown 留档。
  • 服务常驻：Startup 目录 X-Intel.vbs 登录自启；桌面 X-Intel启动.bat 手动拉起；日志 data/service.log。
  • 页面无缓存：所有页面响应带 no-cache 头，系统改版刷新即生效。
  • 统一排序键：推文流、AI 补标、待推送三处均按 COALESCE(NULLIF(published_at,''), created_at) DESC, id DESC 排序。不能用 CAST(tweet_id AS INTEGER)——X 雪花 ID 可用但 RSS 条目 ID 是 md5 十六进制，CAST 恒为 0，会把整源条目压到列表末尾。RSS 入库时 published_at 已统一归一为 GMT 裸值 YYYY-MM-DD HH:MM（RFC2822 的月份缩写不能直接字符串排序）。
  • 地理标签判定：app/geo_rules.py 三层——国旗 emoji（最高置信）→ 强地理词（国名/城市/州省）→ 企业名（仅弱线索，默认不采信）。企业总部所在地不等于涉事国家（"Apple 警告德国议员"应判德国而非美国），FBI/CISA/NCSC 等披露机构名不参与判定。判定依据写入 geo_basis 列（flag/geo/ai/soft_org/geo_recheck/ai_recheck）。
  • 标签复核：python backfill_geo.py --audit 只读复核存量标签（分国旗一致/强地理一致/仅企业名支撑/冲突多国四档）；--audit --fix 用 AI 按"受害方优先"重判并改写；--fix --no-ai 仅清空冲突项待审。脚本用自动提交模式逐条短事务，可与在线服务并行运行。
  • 标签联动：卡片上的基标（国家/分类/行业）与橙色关键词标签 chip 均可点击直接套用筛选；筛选栏「全部标签」下拉来自 /api/facets 的 tags 统计（Top60，精确匹配）；首页 TOP TAGS 卡点击跳推文流并套用同款筛选。
  • 筛选计数动态联动（2026-11-07）：下拉里的计数随当前其它筛选条件实时重算（每个维度统计时排除自身条件）——数字恒等于"在当前条件下选它能得到的真实条数"，不会再出现"显示 36 实际 0 条"。当前选中项计数为 0 时保留显示（0）；筛选组合无结果时提示放宽条件，与"暂无推文可抓取"区分。

8. 给外部工具 / AI Agent 的接入指南

  1. 拉取情报：GET /api/tweets?severity=high&country=美国&limit=20 —— 筛选后的推文自带中文翻译、AI 研判与地理标签，可直接消费。
  2. 按维度分流：GET /api/categories / /api/facets 获取可选维度与计数。
  3. 处理任意外部文本：POST 到 /api/ai/analyze（研判）或 /api/ai/tag（地理标签抽取），无需先入库。
  4. 监听更新：轮询 GET /api/stats 的 last_fetch.at，变化后拉取 /api/tweets?limit=10 获取增量。
  5. 批量导出：/api/tweets?category=数据泄露线索&limit=100 按 16 类分类拉取。

报告任务与 report-writer Agent（写作桥接）

系统不自己写报告——建任务/发线索包/复跑门禁验收/推送，报告正文由外部 ZCode report-writer Agent 按内部报告编写规范产出。状态机：待写 → 写作中 → 已交付待推 → 已推送，验收 FAIL 落「待人工」。

  1. 建任务：页面勾选推文 →「生成报告任务」（或 POST 端点 1），线索包自动落盘，含推文原文/AI 预研判/geo/免责声明（AI 字段仅供参考，必须回原文核措辞）。
  2. Agent 领取：POST …/status {"action":"claim","assignee":"report-writer@<host>"} —— 原子领取，两个 Agent 并发只有一个成功（另一个 409）。
  3. Agent 取料：GET …/package 拿线索包，按其内部规范自行完成外部检索与溯源核查（线索包不替代这两步）。
  4. Agent 写作期间：定期 heartbeat 汇报进度；放弃则 abort 释放回待写。
  5. 交付：POST …/deliver 带 deliver_dir/docx/word_count/ledger_total/ledger_pass/warnings（可选 word_limit）。系统自动复跑已配置的门禁脚本（py -3.13，timeout 180s）：exit 0 → 已交付待推；≠0/文件缺 → 待人工（宁拦住不放过）。
  6. 推送：人工在面板点「推送通知」——企微收 markdown+报告交付附件；其他启用通道按能力收摘要。auto_push=1 时验收 PASS 自动推。

Agent 调度提示词模板（在 ZCode 会话粘贴，{TASK_ID} 换成面板里的任务号）：

领取 X-Intel 报告任务并按规范写报告：
1. POST {BASE}/api/reports/tasks/{TASK_ID}/status，body {"action":"claim","assignee":"report-writer@本机"}
2. GET {BASE}/api/reports/tasks/{TASK_ID}/package 取线索包（AI 字段仅供参考，必须回推文原文核措辞）
3. 按内部报告编写规范完整执行写作与自检（规范不在本仓库内），最后自行运行交付门禁自检
4. 交付回写：POST {BASE}/api/reports/tasks/{TASK_ID}/deliver，body 含 deliver_dir（交付目录绝对路径）、docx（文件名）、word_count、ledger_total、ledger_pass、warnings 数组
5. 系统复跑门禁后：PASS 会停在"已交付待推"等人工推送；FAIL 请读 gate_summary 修正后重新走 3-4
注意：写作期间每完成一大步 POST heartbeat；不要跳过规范任何一步。

① 系统接入 Prompt（作为 Agent 的 System Prompt，一次配置长期有效）

你是接入 X-Intel 威胁情报监控台的情报分析助手。系统 API 基址：{BASE}（无鉴权，仅限内网使用）。

10. 常见问题

  • 抓取全失败？先确认本地代理可用（X 域名被 DNS 污染必须走代理）；故障签名：TCP 能连 10808 但 SSL 握手被重置 = 出口节点问题，换节点即愈。
  • AI 报 429 / 额度用尽？供应商侧额度问题，报错如实显示在推文卡上；换 Key 或充值后点卡上按钮重试。
  • 推文为什么是英文？等 AI 自动翻译完成即显示中文块；也可手动点「翻译」。
  • 时间看不懂？页面时间已按本地时区渲染；数据库 / API 原始值统一为 GMT。
  • 推送没收到？查「推送记录」面板的状态列；企业微信需在内网环境打开消息（截图链接指向内网代理）。
  • 安全提示：系统无鉴权，仅限内网使用；AI Key 明文存于 data/runtime.json，勿外传。
